# Enamel — visual identity

The name is the material: the hard outer layer that protects everything
underneath. That is also what this project is about — an access layer
around clinical data — so the metaphor does some work rather than being
decoration.

| Token | Hex | Where |
|---|---|---|
| `teal-900` | `#0C1B1A` | Ink, body text |
| `teal-700` | `#0D6E63` | Primary. Collection colours, buttons, the mark |
| `teal-300` | `#6FD8C8` | Accent on dark grounds, highlights |
| `bone` | `#FAFCFB` | Page ground |
| `bone-200` | `#EDF2F0` | Panels, table stripes |
| `amber-700` | `#B4762A` | Billing collections — money is not clinical |
| `rose-600` | `#E35169` | Destructive, overdue, no-show |

Clinical software is usually either sterile blue-grey or aggressively
friendly. Teal sits between: it reads medical without reading cold, and
it is far enough from Directus purple that the admin chrome and the
product identity stay distinguishable.

**Type:** Inter for the interface (it is what Directus ships, so the
custom extension matches the surrounding admin without loading a second
family). JetBrains Mono for tooth numbers and codes, where digits must
line up.
